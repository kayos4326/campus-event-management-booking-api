Commands for the video (docs/demo-script.md). Copy and paste these — don't type them live.
Every one of these only reads; nothing here changes the live site.

────────────────────────────────────────────────────────────────────────
0. Connect to the server (do this before recording, leave it open)
────────────────────────────────────────────────────────────────────────
ssh -i ~/.ssh/bad-vps-01_key.pem azureuser@chaotic-hell.eastasia.cloudapp.azure.com

────────────────────────────────────────────────────────────────────────
1. Azure Key Vault  (part 2 of the script)
────────────────────────────────────────────────────────────────────────
# on the server — the only config file, and it holds no secrets
cat ~/campus-event-api/shared/.env

# on your Mac — the real secrets, in the vault (names only, never values)
az keyvault secret list --vault-name campus-event-api-kv -o table

# in the editor, show these two files
#   src/config/keyvault.js   ← fetches the secrets with the VM's managed identity
#   src/server.js            ← waits for them before starting the server

────────────────────────────────────────────────────────────────────────
2. Prisma schema and migrations  (part 3)
────────────────────────────────────────────────────────────────────────
# in the editor
#   prisma/schema.prisma     ← the models
#   src/services/bookings.js ← the seat lock

# the migrations in the repo
ls prisma/migrations

# the same migrations, applied to the live database (on the server)
sudo mysql -e "SELECT migration_name, finished_at FROM _prisma_migrations ORDER BY finished_at" campus_events

# the tables they built (on the server)
sudo mysql -e "SHOW TABLES" campus_events

────────────────────────────────────────────────────────────────────────
3. The API we expose  (part 7) — run on your Mac
────────────────────────────────────────────────────────────────────────
# paste the key you just issued in the Admin panel between the quotes
KEY="paste-the-key-here"

# is room 301 in use right now? (Mi Hsu's event is running, so: active true)
curl -s -H "x-api-key: $KEY" \
  "https://chaotic-hell.eastasia.cloudapp.azure.com/events/api/peer/events/active?room=301"

# the same call with a wrong key → 401
curl -s -o /dev/null -w "wrong key → HTTP %{http_code}\n" -H "x-api-key: wrong-key" \
  "https://chaotic-hell.eastasia.cloudapp.azure.com/events/api/peer/events/active?room=301"

────────────────────────────────────────────────────────────────────────
4. Infrastructure  (part 7) — on the server
────────────────────────────────────────────────────────────────────────
sudo ufw status

# real attacks on this server: attempts, distinct attackers, and bans by fail2ban.
# (Read the logs, not `fail2ban-client status` — its counters reset when the VM restarts.)
sudo grep -h "Invalid user" /var/log/auth.log* | wc -l       # about 9,588
sudo grep -h "Invalid user" /var/log/auth.log* | grep -oE "from [0-9.]+" | sort -u | wc -l   # about 310 addresses
sudo grep -h "Ban " /var/log/fail2ban.log* | wc -l           # about 46 bans

systemctl is-active nginx mysql pm2-azureuser

# on your Mac, from the project folder — the releases on the server
./deploy.sh releases
